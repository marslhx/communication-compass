## 二、共同证据问题

1. **可定位与已核读是两件事。** G16 登记为原始 PDF 超时，草案却引用全文开篇、图及末段；G17 登记为出版者摘要已核，草案给出样本数、页码、表格及讨论原句；G24/G23/G25/G20 等登记也仍是 partial。可以保留 locator 作为待核目标，但应补充实际所读版本、访问状态、正文摘录位置或可复核记录，才能把新命题提升为已审核直接证据。不能仅凭 DOI、目录或作者写出的 support_note 升级。
2. **每项证据须分开定位。** “G16 开篇及末段；GA06 摘要”不能只留在关系总层；要分别写进两项 evidence。整篇页码范围可用于导读，对原创归属、三种位置定义、因果限定等高风险主张则应保留小节、句首、图表号等更小定位。
3. **书目和摘要不是书籍正文。** GA01 只有书目，GA03 为出版者摘录，G11 是目录；NB03、NB04、NB09、NB13 未明确记录实际可读范围。学习推荐可链接书目并说明获取方式，证据却只能支持实际看到的内容。NB01 重印合集应记录重印版本与章页；“获准重印”在本材料中无独立证明，不应据此作授权保证。
4. **direct 不是来源等级。** 原始文献支持直接引文，不能自动支持编辑比较、历史概括或教学迁移。一个主张若混有两种状态，应拆成独立 claim，或整体标 interpretive 并保留归纳理由；“direct + interpretive”不是合法枚举。限制条件也需要同样处理，不能藏在自由文本中免审。
5. **反向支持不成立。** 论文没有研究后来的扩展，可以支持“本节点不覆盖扩展”的编辑范围，不能单凭原文缺席证明扩展的内容或历史。目录列出方法章节可以支持书的覆盖范围，不能自动证明所有具体操作建议。

- **范围**：k1 的“不受限制的讨论”应显式写为 Habermas 概念中的规范条件，避免学生误读为历史公众实际没有限制。反公共、多重公众的判断须保留“分层社会”的条件，不能把它变为任何社会中群体越多越民主。关于种族化群体的历史排斥应对接 NB07 的具体论述，现有范围页码可作为待核目标，不从“存在排斥”自动外推到所有身份。
- **状态与定位**：k2 混用 direct/interpretive，应拆分并同时列 G19、G23；不能只把 G23 写在说明里而不进入 evidence。G19 书目支持研究范围，不支持全部章内容。G23 Section 1 与句首定位较好，G23 登记仍要求正文定位核验；NB07 原文 access_status 未记录，需补。controversy_note 将欧洲中心、理性规范等并列为“持续批评”，超过明确列出的证据时应缩至已核的排除、不平等及单一公众假设。
- **关系**：使用 developed 而非首次提出是合适的；但“最具影响力的一种”没有相应比较材料，最小删去，保留具体历史研究和概念发展贡献。公共意见 addresses 的 target 类型需核：若 r5-public-opinion 是 concept，现本体不允许 addresses 指向它，不能仅因名称自然就放行。其余政治传播、性别研究边要核 research_topic 类型。对女性主义范围需明确是理论批评后的展开，不能归为原初模型已解决。
- **学习资源**：G23 简明文章适合入门导读；G19 整本和 Fraser 论文都不宜默认 introductory。当前给 G19 的“全书”过重，应在取得正文后指定少量章节；在此之前显示为中级/进阶参考书及书目入口。

### 9. r7-platform-governance：needs_revision

- **可保留**：跨主体治理、法规与执行效果分开；中国两项制度与欧盟比较样本分开；已有 as_of、last_evidence_check、next_review_due，以及中国状态核对来源 NB15/NB16。
- **法域与时效**：本报告未联网，不能确认 2026-09-11 的法规现行性；可记录“草案据 NB15/NB16 核对”，待正式来源记录给 access_status。欧盟 NB12 尚无与中国对应的版本/时效核对记录，应标“2022 年文本的比较样本，适用版本待核”，不能让整节点 as_of 被读成中欧全部制度都已更新至该日。DSA 第34—35条的适用对象必须从现有条文原文补准确范围；“大型平台”不足以作为具体法律适用类别。
- **主张粒度**：算法种类范围不等于每种算法/每个提供者适用全部相同义务。候选边把解释、关闭、备案合写为全部算法的通用处理，必须按条款限定主体、服务和义务；特别是备案的适用门槛，当前说明未给，待核原条文后补，不能凭记忆写入。用户标签/选项支持与隐私、自主交叉的解释，不直接证明完整“监视”研究主张。summary 的“中国现行制度突出……”应明确仅据两项制度样本作有限归纳。
- **定位与直接性**：NB08 摘要可支撑多主体定义；NB09 出版者内容简介不能自动支持 chapters 1–2 的所有具体动作和判断，“长期缺乏相称公共审视”若只是书籍论点需显式归属并限定 2018 年论述。法条条号定位较好，但比较框架、信息失序及隐私交叉关系应标 interpretive，不能用 `direct_with_scope_limit` 掩盖推理。
- **关系硬错误**：节点 type 为 research_topic，而 addresses 只允许 theory_model/concept/tradition 发出。三条 `r7-platform-governance addresses ...` 全部不合规。**最小修订优先改内容**：迁入 learning_links/主题说明，不扩宽本体为泛相关边。`builds_on r3-platformization` 仅“承接问题”的编辑归纳，缺思想/理论承接证据，亦暂缓并改学习链接。
- **复核规则**：过期撤下“当前”标签是合理展示措施，不应等同内容自动失效。半年复核日是编辑安排，不是法规半年前必然有效的保证。重大变更触发提前复核可保留，建议入独立维护规则或新增可选 review_trigger。
- **学习资源**：Gorwa 是合适中级概念入口；Gillespie 应指定取得过的章节并标难度；中国两项法规应拆成两个资源对象，提供具体条文导读。法律条文适合课堂比较材料，不应作为完整平台治理入门的唯一解释资源。

### 10. r8-content-analysis：needs_revision

- **可保留**：抽样、单元、编码、语境推论；多人编码报告一致性；可靠性不等于效度；自动化不等于解释力；内容本身通常不能直接证明受众效果/生产意图/因果。已经明确把无直接应用证据的信息失序边排除公开图谱，这一做法应保留。
- **摘要分类**：人工/计算是执行方式，解释型文本研究是相邻方法取向；将三者列为同层“三种”会淡化已在正文提及的质性内容分析，并把邻近方法混成内容分析内部分类。最小改写应围绕内容分析的明确材料单位、编码框架与有限推论说明人工/自动化可组合，将与解释型研究的比较放到边界段；不新增方法史事实。
- **信效度**：G25 现有登记明确支持一致性评估/报告，尚不足以把所有信度/效度论述都标 direct。两者区分可作为 interpretive 的必要教学边界，若要作为方法定义事实发布，应在 G20/G25 已有材料中取得确切章节/段落证据。“编码者间一致性是必要质量信息”需限定多人、基于分类编码的设计，不推广成所有质性/解释型研究的一律要求。不要发明统一系数或阈值。
- **证据定位**：G20 Chapter 2.1 对定义适当，Chapters 4–8 对完整流程过宽，目录只支持这些主题被覆盖；G25 全文页段、NB14 全文分类未给实际 access_status。方法程序中的独立验证、模型版本、错误分析可作为编辑质量要求保留，但不能据自动化综述摘要宣称这些具体步骤都是作者原话。NB13 方法教材若作为已有方法的综合说明，source_type 建议 scholarly_synthesis；同理 G20 应按实际使用角色审核，而非因作者著名自动判 primary_scholarship。
- **关系**：`used_in r5-journalism` 方向合规，但 G18 个案和 G25 摘要不足以直接支持 statement 罗列的主题、来源、框架、呈现、选择结果全部范围，最小缩至实际实例支持的材料分类与选择结果，其他待核。`r8-computational builds_on r8-content-analysis` 把整个计算传播压成内容分析后继，现有 NB14 仅支撑其自动内容分析分支；改为学习链接或限定到合适的细分目标，暂缓现边。与解释型方法 contrasts_with 的另一端缺专门文献，**hold**；不能把“interpretive_pending_cross_review”当可公开的 interpretive。`used_in r4-info-disorder` **hold**，保留 pending、空证据及明确待核任务，不伪填“待补”作为 locator 通过审核。
- **学习资源**：G20 全书对初学者过重，G25 信度论文应接在编码练习之后，NB14 为中级工具比较。现有 NB13 可纳入质性路径导读以匹配正文范围，但须先确认实际可读章节。无需假设三个英文原典本身已经构成本科零基础学习路径。

### 4.2 relation.schema.json 与关系集合

- A 使用 `source/target/statement/status`，B 使用同名展示字段和复合 status；应映射为 `source_id/target_id/statement_zh/evidence_status`，另置 `review_status`。补 id、reviewed_at；范围说明集中放 scope_note。`direct_ready_for_review`、`direct_with_scope_limit_ready_for_review`、`interpretive_pending_cross_review` 都不是枚举，应拆状态而非新增枚举。
- 关系 evidence 不能是来源 ID 字符串或说明句；每项必须是完整证据对象。A/B 多来源的总 locator 应逐来源拆分。
- **端点语义验证必须加入外部校验器**：JSON Schema 单条记录无法查询节点 type。明确阻止 concept→has_concept 与 research_topic→addresses；对 r5-public-opinion、r5-political、r5-journalism、r6-gender、r7-algorithm 等未在十节点内定义的目标标待合并类型核验，不凭 ID 猜测。
- **不要为保留边放宽本体**。平台治理发出的三个 addresses、过程入口的 has_concept 优先移学习链接；问题迁移不自动等于 builds_on；关系已标 interpretive 也不能绕过端点约束。
- A 的 Hall proposed 编码/解码、Hall associated_with 文化研究重复，合并为一个规范关系记录；对称 contrasts_with 需要固定存储方向与去重，不保存互相反向的两条。
- 对 reviewed/published 增加非空 reviewed_at 与非 pending 的限制；当前 Schema 只限制枚举及证据数，无法阻止“pending + reviewed + null date”形式上的假通过。scope_note 涉及高风险归属与跨法域边时应由审核规则强制，而非依赖可选字段自愿填写。

## 五、修订完成条件

1. 主代理完成内容最小修订，尤其处理错误端点、混合证据标签及无法支撑的范围扩张；保存明确的暂缓关系清单。
2. 十节点及其实际保留关系、来源转为标准记录并通过字段和集合校验；本文建议的少量 Schema 变更需同步本体版本，不能只改验证器。
3. G16/G17/G22/G23/G24/G25/G20 与各 GA/NB 来源按实际核读内容补访问记录。未取得全文的主张保持 pending 或暂不发布，禁止仅补 locator 字符串造成立即可审核的外观。
4. 针对修订后的高风险命题再次异模型复核：原创归属、思想承接、法条适用、时间状态、方法有效性。审核模型的结论不代替学术来源。
5. 为学生提供可以实际使用的短学习路径、资源难度、选读定位和访问范围。只有参考书目列表，不足以验证“下一步去哪里学习”的产品结构。
