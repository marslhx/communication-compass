# 内容状态与前端展示规则

更新日期：2026-09-15

本文件把本体中的证据、审核和访问状态转换为前端必须遵守的选择规则。它不是一套新的学术分级。

## 节点成熟度

`record_level`记录字段结构，`review_status`记录编辑进度；两者不能合并。“complete”只表示字段齐全，旧文档中的“完整样本”不意味着知识覆盖完整或已经定稿。前台不再使用“待审核”这种容易让人联想到正式同行评审的说法，而把首版内容视为持续开放校订的教学导航。

| 数据条件 | 团队用语／展示标签 | 允许展示 |
|---|---|---|
| `record_level=candidate` | 候选入口 | 名称、类型、导航归属、入选说明、来源线索 |
| `record_level=complete` 且含 `pending` | 部分内容待核 | 已有正文、已核与解释性主张、单独的待核区；待核内容不进入摘要或关键结论 |
| `record_level=complete`、无 pending、`review_status=ready_for_review` | 开放校订 | 字段齐全的正文与证据，可以用于首版导览，并继续接受读者纠错 |
| `review_status=draft` 或 `needs_revision` | 资料整理中／需修订 | 按已有证据范围展示，不声称定稿；pending仍须隔离 |
| `review_status=reviewed` | 已完成基础校核 | 完成下述编辑检查；仍显示证据类型和校核日期，不表示同行评审或专家背书 |
| `review_status=published` | 已发布 | 满足发布规范的正文；仍显示来源访问范围和复核日期 |

基础校核只要求：结构校验通过；公开关键结论没有pending；direct／interpretive标签与所列来源相符；人物身份和动态事实检查到标注日期；完成一次编辑通读并留下修订记录。争议性或高风险条目可以另请教师、研究者复核，但不把这一要求机械地施加给每个首版节点。

学习链接不会改变目标节点的成熟度。含任一pending主张的节点不得标为已完成基础校核；无pending也不会由脚本自动升级。正式上线后设置专门反馈入口，读者纠错经查证后进入修订记录。

深度审计A/B/C只按照资源、学习链接、direct主张、关系数量和pending缺口排队，不是上述校订状态，也不等于研究来源等级。A类节点也可能仍处于开放校订；已完成基础校核的节点也可能是B类。不得为满足A类数量门槛补造关系。

## 主张证据

- `direct`：标签“来源直接支持”；展示 locator 和 support note。
- `interpretive`：标签“编辑归纳”；紧邻显示归纳理由，不能缩成与 direct 相同的无说明徽标。
- `pending`：标签“待核”；不进入摘要、搜索摘要、知识卡关键结论或默认图，只能在详情页“待核与版本差异”区显示。

## 关系图层

默认学术图同时满足：

1. `review_status` 为 `reviewed` 或 `published`；
2. `evidence_status=direct`；
3. 关系端点存在且类型通过本体校验；
4. 关系文字、范围说明和证据可展开查看。

“证据透明／编辑比较”图层只显示已复核的 `interpretive` 关系，并使用与默认图不同的线型和明确图例。`pending` 关系不进入任一公开图层，只保留在编辑审查记录中。

## 来源访问范围

| 值 | 页面文案 |
|---|---|
| `full_text` | 已核全文 |
| `excerpt` | 已核片段 |
| `abstract` | 已核摘要 |
| `metadata` | 仅核书目信息 |
| `unavailable` | 当前不可访问 |

访问范围不等于来源品质，也不等于某项主张一定获得直接支持。任何证据卡仍须显示 locator 与它实际支持的内容。

## 动态节点

`temporal_profile=evolving` 时，页面必须同时展示 `as_of`、`last_evidence_check`、`next_review_due`。超过复核日期显示“需要重查”，不自动写成“已经失效”。法规、平台政策和前沿条目必须把法域、版本或适用主体写在可见正文中，不能只藏在证据折叠区。
