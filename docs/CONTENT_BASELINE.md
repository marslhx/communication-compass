## 深度审计如何使用

A要求至少2项学习资源记录、3条学习链接、2项标为direct的主张、1条已复核文献关系且无pending；B缺1—2项且无pending；C缺3项以上或含pending。脚本只计记录数量与状态，没有自动判断资源是否真正分层、学习理由是否充分、来源是否直接支持主张。A类可以待审，已审核节点也可以是B类；无可定位证据时，零关系是可接受的编辑决定。

完整逐节点列表见[内容深度审计](../content/reviews/content-depth-audit.md)。正文质量仍需检查定义、问题、适用条件、反例与争议、具体案例、下一步学习，以及中英文名和历史归属，不能靠把记录补到数量门槛完成。

## 复现与历史记录

```bash
python3 scripts/validate_content.py
python3 scripts/check_content_rebuild.py
python3 scripts/audit_content_depth.py
python3 scripts/audit_release_readiness.py
```

前两项只校验正式数据或在临时目录隔离重建，不覆盖正式数据；后两项会更新审计报告。深度审计默认使用执行时北京时间；需要生成明确标注的日期快照时可使用`--as-of YYYY-MM-DD`。它只标记报告日期，不恢复当日数据，也不改写审核或来源日期。研究输入变化后，应先按[来源重建说明](../research/SOURCE_REBUILD.md)核对隔离差异，再运行正式规范化和装配，重跑检查并更新本基线；不得直接编辑生成来源表。
