## 原因与输入追溯

旧规范化器只读取 `source-register-node-drafts.csv`、`source-id-map.csv` 和 `decolonial-sources.json`，得到 87 条。检查现存研究登记、内容草稿／修订输入与临时材料后，没有发现 T001、S040–S130 的独立完整来源登记或可恢复生成脚本；修订节点／关系只有引用，不能据此补造完整书目或访问记录。首页补证另有明确的 `home-start-source-updates-2026-09-14.json`，含 S010 的定点更新及新增 H01、H02。

因此本轮采取经主代理确认的无损登记迁移：从修复前 `content/data/sources.json` 快照原样迁出 92 条到 `migrated-expansion-sources-2026-09-14.json`，形成今后受版本控制的显式输入。**它的历史来源是旧正式输出，不是新发现的独立证据；工程迁移不等于来源重新核验。** 未复制 PDF、全文提取或页面图。

逐 ID 清单见 [迁移 provenance](source-migration-provenance-2026-09-14.json)：记录原快照 SHA-256、181 条总量、迁出的 92 个 ID、每条原始字段摘要及原访问日期／范围。记录摘要使用按顶层键排序、UTF-8、无多余空格的 JSON SHA-256。现存完整书目与访问记录逐字段保留；后续如需更正，添加有依据的补丁，不重写这份历史迁移输入及其校验清单。

## 安全检查与维护

默认无写入检查：

```bash
python3 scripts/check_content_rebuild.py
python3 -m unittest discover -s scripts/tests -v
```

第一条在系统临时目录运行规范化、装配和校验，检查全部知识点引用（含教育经历）、关系证据引用，再与正式五份 JSON 逐字段及顺序比较。任何差异都会返回非零并列出 ID／字段，不修改正式数据。当前15项回归测试还覆盖268来源基线、历史迁移不变、来源与知识点显式覆盖护栏、P1九知识点最低教学深度、全部24个动态知识点的证据边界与日期顺序、N01版本及C17署名、知识点／关系的新旧审核日期、Q341–Q350的全文升级，以及人物首批教育和肖像许可边界。未来有依据的新增来源，应同步更新测试中的批次总量预期。

修订输入后，差异本身可能是预期的；不能为让检查变绿而盲目覆盖。先在隔离目录检查预期差异：

```bash
python3 scripts/normalize_research_data.py --output-dir tmp/content-rebuild
python3 scripts/assemble_content.py --data-dir tmp/content-rebuild
```

确认变更依据和差异后，才运行正式 `normalize_research_data.py`、`assemble_content.py`、`validate_content.py`，再运行隔离一致性检查与两项审计。若要删除一个已登记来源，默认规范化会阻止；应单独复核引用与删除范围，不使用跳过护栏的参数。
